| 配置键 | 默认/最大值 | 含义 |
| --- | --- | --- |
| enabled | True | 开启受控查询循环；False 回退原只读路径 |
| maxSteps | 3 | 包含首次规划，Loop 容器也固定最多 3 次 |
| maxToolCalls | 3 | 最多 3 次经校验放行的白名单调用 |
| maxRepairs | 1 | 修正仍占规划/查询次数；没有确定修正证据时不可重试 |
| maxLlmCalls | 5 | 请求模型总预算，包含已有写意图识别一次 |
| softDeadlineSeconds | 90 | Start 后捕获时间，每个新规划/查询前检查 |
| pageSize | 20 | 默认页大小，不覆盖更小的用户上限 |
| maxCollectedRecords | 60 | 代码侧证据集合上限，含资源解析结果 |
| maxObservationChars | 6000 | 所有轮次模型可见观察的合计字符上限 |
| maxStateBytes | 32768 | 请求内状态 UTF-8 字节上限 |

整数只能向下调整；负数、错误类型或超出上限使用安全默认值。摘要最低 512 字符、状态最低 4096 字节。开关只接受原生布尔值。默认复杂路径最多写意图识别 1 次 + 规划 3 次 = **4 次显式 LLM 调用**，低于总预算 5；本期结果使用确定性模板，循环不进入旧 `summarize`。简单成功查询首轮结束，最后一次工具后不再追加规划/反思/总结模型。旧单步调用路径保持原节点与模型。

90 秒是步骤之间的软预算，不能中断阻塞中的模型或 HTTP 调用。未给节点添加本地版本未确认的超时字段，不承诺端到端 90 秒。字符/次数限制也不是精确 token 或金额预算，AI 服务的每日配额不覆盖 Dify 文本模型。

## 策略与接口边界

首次合法规划额外携带经校验的 `task`，冻结最终工具、完整条件和目标；依赖查询也必须携带最终筛选。后续禁止改写 `task`、计数和终态。成功证据才能覆盖目标，模型 `FINISH` 不能自行证明完成。未知字段、重复 JSON 键、错误类型、非有限数字、越界分页及未授权 ID 会终止为 `FAILED`，已有真实成功证据时为 `PARTIAL`；资源重名或不完整另行澄清。

允许的必要连续查询：

1. 真实普通相册/人物列表 → 完整列表中的唯一精确名称 → 本次短引用解析 → 同条件组合查询。两个资源依赖最多三次调用。列表不完整、重名、脱敏改变名称或未知引用时澄清，不取第一页的默认项。本期不自动遍历不完整资源列表。
2. 明确数字数量 → 第一页成功且 `hasNext` → 同条件下一页。页大小在本次查询内固定，避免改变分页偏移；按数量选择不超过默认页大小的约数，例如 30 张用每页 15。质数等数量可能只能使用较小页大小，三次调用仍不够时返回已验证部分结果和预算停止，不扩大上限。未明确数量时一页即结束。
3. 用户明确允许另一精确标签 → 原查询为空 → 获取真实标签列表 → 唯一可用且已授权标签查询。仅支持单标签 OR 的一次替代，其余条件保持冻结；多个可用替代标签需澄清。不做语义同义词猜测，不把人物分组当标签，不根据 `relaxSuggestions` 放宽条件。

相对日期采用 Start 捕获的参考时间与 Asia/Shanghai。支持今天、昨天、今年、去年、最近 N 天；规范化后冻结。上周、上个月等尚未支持或语义不确定时要求明确日期。明确日期需在当前请求中出现。跨消息“继续/下一页”、相似发现及短答仍进入原路径，保留旧规划器最近 8 轮上下文。原生记忆不能区分既有写入和只读轮次，因此新 Loop 首轮及后续轮次只接本次脱敏任务与证据，不额外重复聊天历史；依赖未明确历史对象的请求可能要求重述。本期不新增持久查询记忆或查询到写预览桥接。

短答续页修正（2026-10-04）：`read_continuation.py` 统一“是、好、可以、行、嗯、同意、ok”等常见短答。入口将其交给原有上下文路径；仅当上一条助手消息唯一、明确询问是否翻页，而且最近成功查询的工具、完整条件、实际页码、size 和仍有下一页可恢复时，肯定词才表示继续一页。工具与筛选、排序和 size 全部沿用，只增加 current；“不用”等否定词停止，末页不重复查询，上下文不明或多选问题针对原问题澄清。这是基于旧规划器最近 8 轮的提示规则，尚未运行模型验证，不是新增持久分页状态或确定性历史解析器。存在 pending 时，扩充后的含糊词集合仍被原校验节点拦截；“继续下一页”可表达明确只读意图。“确认/执行”等保留为写确认专用词，即使没有 pending 也不作为翻页别名。静态检查只允许上述原只读两处精确差异，不豁免原写节点。

传输错误回复修正（2026-10-04）：工具 fail 分支的 `TRANSPORT_ERROR` 现在说明“查询服务请求失败，请检查后端状态、服务地址及代理连接”，不再统一说返回结果校验失败。实际收到数据但格式不合法时仍报告格式校验问题；不展示内部 URL，不新增重试。该修正已随本次 DSL 生成同步，未启动后端或发起验证请求。

九个工具逐项适配：`searchFiles` 的 `time/fileList` 分组展开为照片；`advancedSearchFiles` 的平面照片分页；普通/地点/设备/人物分页；裸标签列表；能力清单；图库健康统计和建议。只接受业务 `code==200` 和合法结构；text/json 的单元素包装可兼容，两份 envelope 不一致则拒绝。失败分支即使有似乎成功的结果也不算成功。

`searchFiles` 的 `tagName/searchType` 分支会忽略部分其它筛选，新循环拒绝这些会吞条件的组合，要求组合接口。OpenAPI 中历史 `advancedSearchFiles.searchType/searchKeyword` 不属于当前 DTO，新循环拒绝它们，只使用 `keyword`。旧布尔完整性字段可输入并严格转换成三态枚举，避免向 Dify Code 输出 nullable boolean。ID 仅从本次真实普通相册/人物证据解析，并限制在原生数值安全整数范围；不支持直接由模型提供 ID。

当前后端 `BaseResponse` **没有结构化唯一无损修正协议**。修正上限、原因和证据门禁已有实现，实际适配器返回 `repair=None`，参数业务错误立即停止；不能以“最多一次修正”为由猜测重试。

组合接口的 `conditionSummary` 可核对名称、地点、标签关系、媒体与完整性；当前只回显“拍摄/上传时间范围”，没有日期边界，无法独立证明实际 SQL 日期范围。代码冻结并发送边界，回复区分已发送边界与后端摘要。旧照片接口没有同等条件证明。自然语言首次抽取仍可能遗漏用户意图，需人工比较请求、实际参数和生效条件；不能宣称完全证明语义正确。

工具自由文本按外部数据处理。模型只见脱敏观察和短引用，真实 ID 保留代码证据映射；URL、内部路径、向量、凭据和错误原文不进入下一轮规划或回复。Dify 原生工具执行轨迹可能保留工具原始输入/输出，仓库策略不能改变平台底层审计记录；因此实际实例应限制轨迹访问与保留范围，勿将原始工具轨迹作为公开日志。新代码不另行建立日志系统。
