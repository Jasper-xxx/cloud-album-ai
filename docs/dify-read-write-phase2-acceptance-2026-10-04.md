## 修复与边界

- 源和目标相册原先可能要求重复 `listAlbums`，被无进展保护拒绝；现在同一次完整列表证明两者的唯一性，保留重复调用保护。
- 在线模型曾忽略目标解析顺序，或把目标相册/示例引用当作源范围，分别被 `BRIDGE_FIRST_GOAL`、`RESOURCE_NAME_SOURCE`、`RESOURCE_NOT_UNIQUE` 拒绝。现在桥接使用短提示和代码生成的每轮只读计划，目标名称留在代码侧；模型输出仍经过原严格范围与证据校验，不放宽校验换取成功。
- 附件保存意图原先接受「保存附件然后删除全部」；现在复合写指令、否定和询问要求澄清。此项通过 Code 节点测试，未执行附件上传全流程。
- 只读回复清理器曾将代码产生的确认指引误判为模型伪造确认；现在保留确定性 pending 短答指引，并已在线复验。

多页全部范围、预算耗尽、重名/不完整列表、截断和未知引用等已通过相关离线契约，没有制造在线故障。相册实际确认写入、浏览器视觉流程、账号 B 独立登录鉴权、全部附件/P3/P4/AI 后台任务仍不属于本轮重点验收。并发分页没有数据库快照协议的既有限制继续保留。
