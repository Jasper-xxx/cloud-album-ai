## 一、文档用途

本文是云忆助手“当前实际功能”的持续清单，用于回答以下问题：

- 用户目前可以让助手完成什么。
- 哪些功能必须确认后才能执行。
- 哪些能力仍在开发、验证或明确禁用。
- 后端接口、OpenAPI、Dify 工作流与评测是否保持一致。

功能方向和后续优先级见 [智能体拓展方案](./智能体拓展方案_持续更新.md)。本文只记录当前状态，不把规划中的能力描述成已经可用。

## 二、状态定义

| 状态 | 含义 |
|---|---|
| 可用 | 已接入当前智能体链路，现有版本可使用 |
| 已实现，待验证 | 代码或配置已经落地，但本轮完整验证尚未通过 |
| 进行中 | 只完成了部分层级，暂不能视为完整交付 |
| 规划中 | 已列入拓展方案，尚未实现 |
| 禁用 | 当前明确不向智能体开放 |

## 三、当前功能总览

### 3.1 只读查询

| 功能 | 用户可以表达的需求 | 后端工具 | 状态 |
|---|---|---|---|
| 查询能力边界 | “你能做什么” | `getAgentCapabilities` | 可用 |
| 检索照片 | 按标签、地点、设备型号、普通相册或媒体类型查找照片 | `searchFiles` | 可用 |
| 组合检索照片 | 组合日期、多标签、地点、设备、普通/人物相册名称、媒体类型与数据完整性条件 | `advancedSearchFiles` | 已实现，待用户验证 |
| 图库健康分析 | 统计未标签、缺失元数据、相似文件、异常 AI 任务和未归相册文件，并给出只读建议 | `analyzeLibrary` | 已实现，待用户验证 |
| 查询普通相册 | 查看当前用户的普通相册 | `listAlbums` | 可用 |
| 查询地点相册 | 按国家、省、市、区县查看地点相册 | `listLocationAlbums` | 可用 |
| 查询设备相册 | 查看设备品牌或型号聚合的相册 | `listModelAlbums` | 可用 |
| 查询标签 | 查看当前用户已有标签及其照片数量 | `listTags` | 可用 |
| 查询人物相册 | 查看当前用户的人物相册，可筛选显示或隐藏状态 | `listPeople` | 可用 |
| 单工具查询路由 | 根据结构化意图只调用一个必要工具，避免固定并行调用全部工具 | Dify 查询规划与路由节点 | 已实现，待验证 |

照片检索当前支持：

- 分页，单页最多 50 条。
- 按拍摄时间或上传时间排序。
- 图片、GIF、视频或全部媒体类型。
- 国家、省、市、区县地点条件。
- 普通相册 ID。
- 全部照片或未打标签照片。
- 精确标签。
- `tag`、`model`、`location` 三类关键词检索。

P1 组合检索额外支持：

- 拍摄时间或上传时间范围，接受日期或 ISO 本地日期时间。
- 最多 20 个标签，支持 `AND` 与 `OR`。
- 通过 `albumName` 和 `personName` 按当前用户的普通相册名称、人物分组名称做精确交集检索；人物分组不使用照片标签代替。
- 国家、省、市、区县、设备品牌与型号组合。
- 普通相册 ID、人物相册 ID，以及是否尚未加入普通相册。
- 图片、GIF、视频多选；已打标签、未打标签或全部。
- 是否缺少地点、特征或成功的 AI 分析结果。
- 拍摄时间或上传时间排序、分页、总数、总页数和是否还有下一页。
- 条件摘要；空结果时返回按标签关系、日期、地点、相册或数据完整性逐步放宽的建议。

图库健康分析只读统计文件总数、未标签、缺失地点、缺失特征、缺失 AI 分析、疑似相似组、失败或停滞 AI 任务和未归普通相册文件，并返回 0～100 健康分、健康等级及按优先级排列的建议。分析不会自动修改照片、补写元数据、提交任务、合并或删除文件；需要写入标签或相册时仍进入 P0 预览与确认链路。

能力清单模式标识已更新为 `trusted_agent_full_p0_p4`。

### 3.2 P2 AI 标签建议与任务跟踪

| 能力 | 当前实现 | 状态 |
|---|---|---|
| 标签任务预览 | 使用文件 ID、P1 组合条件或相册/标签/地点/设备简化条件冻结最多 50 张图片 | 已实现，待用户验证 |
| 确认后提交 | 消费 P0 一次性凭证，为每张图片创建独立 `autoAdd=false` 持久化任务 | 已实现，待用户验证 |
| 批次任务状态 | 聚合等待、运行、成功、重试中、最终失败数量和进度 | 已实现，待用户验证 |
| 候选标签 | 每张图片最多返回 5 条达到阈值的标签及置信度 | 已实现，待用户验证 |
| 候选选择 | 支持全部、按标签名称或精确文件—标签对选择，单次最多 100 条 | 已实现，待用户验证 |
| 可信写入 | 候选必须来自当前用户任务结果，再次预览、确认后才能写入 | 已实现，待用户验证 |
| 自动重试与幂等 | 复用持久化任务自动重试；批次作用域允许重新发起，P0 凭证保证同次提交幂等 | 已实现，待用户验证 |

P2 标签任务不会在识别完成后自动写标签。任务完成只产生建议；共享给其他活跃用户的物理文件在最终写入时继续安全跳过。P4 已提供独立附件桥接，但附件必须先取得真实 `fileId` 才能成为 P2 任务目标。

P2 简化筛选支持 `searchType=latest` 与 `selectionLimit=1～50`。例如“为最近 5 张图片生成 AI 标签建议”会按上传时间倒序冻结最近 5 张当前用户图片；该步骤仍只生成待确认预览，明确确认后才提交 `autoAdd=false` 任务。

P2 批次聚合以底层异步任务真实成功状态 `SUCCESS` 为准，对外继续返回 `SUCCEEDED`。预览、任务提交和状态查询均携带目标照片的原始文件名与真实 `fileId`；Chatflow 按照片展示候选标签，并明确提示“生成建议不会修改照片”。只有再次预览并确认应用建议后，标签才会写入，执行结果会列出实际发生变化的照片。

### 3.5 低风险整理操作

相册整理：

| 功能 | 业务效果 | 状态 |
|---|---|---|
| 创建普通相册 | 创建一个普通相册 | 已实现，待验证 |
| 创建相册并加入照片 | 创建相册，或复用已有同名相册，再加入匹配照片 | 已实现，待验证 |
| 加入已有相册 | 将匹配照片加入当前用户的目标相册 | 已实现，待验证 |
| 移出相册 | 只解除相册与照片的关联，不删除照片文件 | 已实现，待验证 |

标签整理：

| 功能 | 业务效果 | 状态 |
|---|---|---|
| 添加标签 | 为当前用户的匹配照片添加标签，已有标签不重复写入 | 已实现，待验证 |
| 移除标签 | 从当前用户的匹配照片移除指定标签 | 已实现，待验证 |

写操作当前约束：

- 必须先预览，后执行。
- 单次最多冻结并处理 100 张照片。
- 照片必须属于当前登录用户且未被删除。
- 预览为空时不签发确认凭证。
- 相册移出操作不会删除照片文件。
- 执行结果区分照片实际变化数、跳过数和新建相册数。
- 创建空相册时，照片变化数可以为 0，但相册创建仍可成功。
- 纯创建相册始终冻结空照片集合，不受残留筛选参数影响。
- Chatflow 对“只创建/新建一个相册且未选择照片”的请求确定性归一为 `create_album`，不会误用“创建相册并加入照片”并要求非空图片范围。
- 已存在相册按预览冻结的相册 ID 执行；确认前被删除或改名时拒绝改投其他相册。
- 同一用户的相册创建按用户行锁串行化，降低同名相册并发分叉风险。
- 标签写入只处理当前没有其他活跃用户共同持有的物理文件；共享文件会明确跳过，避免改变其他用户看到的全局标签。
- 相册和标签整理支持 `searchType=latest` 与 `selectionLimit=1～100`；例如“把最近上传的 3 张照片加入某相册”会按上传时间倒序冻结最多 3 张，而不是固定只取 1 张。
- 相册、标签、P2 与 P3/P4 的预览会在后端可解析到目标文件时返回原始文件名和真实 `fileId`；执行结果只在能精确确认实际变化范围时返回对应照片清单，避免把跳过项误报为已修改。
- Chatflow 只展示一次后端确认提示，不再重复拼接摘要；预览回复会列出服务端冻结的照片，执行回复会列出实际发生变化或被处理的照片。

待执行状态包括：

```text
PREVIEWED -> EXECUTING -> SUCCEEDED
                       -> FAILED
PREVIEWED -> CANCELLED
PREVIEWED -> EXPIRED
```

说明：

- `confirmedAt` 记录确认时间，不单独暴露 `CONFIRMED` 持久状态。
- 过期、取消、失败或已被其他请求领取的凭证不能启动新的业务写入。
- 用户可用“状态 / 查询状态 / 执行状态 / 查询执行状态 / 查看状态 / status”查询当前待执行状态。
- 用户修改相册名、标签或范围时必须完整重述新需求并重新预览，不从历史中恢复旧选择参数。
- 完整并发、重放、事务回滚和跨用户验证尚未完成，因此本节暂不标记为“可用”。

| `POST /agent/executeP3Action` | `executeP3Action` | 确认后执行 P3 操作 |
| `POST /agent/uploadAttachment` | `uploadAttachment` | 上传聊天附件并返回真实 `fileId` |
| `POST /agent/searchByAttachment` | `searchByAttachment` | 使用聊天附件以图搜图，不自动上传 |
| `POST /agent/previewP4Action` | `previewP4Action` | 展示分享、下载或删除影响并签发短期凭证 |
| `POST /agent/executeP4Action` | `executeP4Action` | 确认后执行服务端冻结的 P4 操作 |

执行接口不再接受 `action`、`fileIds`、`albumId`、`albumName`、`tagName` 或筛选条件。业务参数只能来自预览阶段保存的服务端载荷。

## 五、Dify 对话流程

### 5.1 只读流程

目标流程：

```text
用户问题
  -> 结构化查询规划
  -> 参数校验与歧义判断
  -> 选择一个必要工具，或直接澄清
  -> 根据工具真实结果回答
```

路由原则：

- 只有询问能力边界时才调用能力清单。
- 单条件照片检索使用 `searchFiles`；组合条件使用 `advancedSearchFiles`。
- 图库健康、整理优先级和异常项统计使用 `analyzeLibrary`。
- 相册、标签和人物查询分别调用对应工具。
- “继续/下一页”或只修改一个筛选条件时，查询规划节点使用最近 8 轮只读对话复用其余条件；无法可靠恢复时先澄清。
- 参数不足且可能改变结果时先澄清。
- 工具结果是数量和业务状态的唯一事实来源。

### 5.2 写操作流程

目标流程：

```text
用户提出整理需求
  -> 提取并校验预览参数
  -> 调用 Preview
  -> 确定性保存待执行凭证
  -> 向用户展示自然语言预览
  -> 用户独立、明确确认
  -> 调用 Execute
  -> 展示真实执行结果并清除会话状态
```

如果用户修改相册名、标签名、照片范围、目标或操作类型，必须重新预览，不能复用旧参数执行。

## 六、安全与能力边界

### 6.1 明确禁用

- 修改用户账号信息。
- 绕过预览直接执行写操作。
- 超过单次上限的大范围自动写入。
- 绕过 90 秒 P4 短期确认执行分享、下载或删除。

### 6.2 当前不具备

- 根据人物照片自动推断真实姓名、关系或敏感属性。
- 超过安全上限的一次性永久删除或清空回收站。
- 修改用户账号、认证或存储配置。

### 6.3 人物与隐私规则

- 不能推断人物真实身份。
- 不能推断年龄、民族、健康状况等敏感属性。
- 人物名称和关系只能来自用户明确输入。
- 不返回 API Key、数据库密码、MinIO 密钥、JWT 密钥或原始特征向量。
- 所有业务查询和写入必须限定在当前登录用户范围。
